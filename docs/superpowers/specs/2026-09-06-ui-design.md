# thisconnect UI — Design

Status: approved for implementation planning.
Scope: the `/ui` Tauri v2 app — the full v1.0 GUI surface per `docs/SPEC.md` §2, §7.4, §9.

This document is a design, not a spec amendment. Nothing here reopens or resolves
`docs/SPEC.md` §13 items 4-6 (full-tunnel toggle, MTU field, `allowed_cidrs` default) — the
v1.0 UI exposes only v1.0 fields, and those items stay open in SPEC.md, untouched.

---

## 1. Why this shape

`docs/SPEC.md` §7.4 already settles the contract: line-delimited JSON over the daemon's
AF_UNIX socket, GUI never sends a raw `.ovpn`, no JSON-RPC framing. §9 already rules out a
sidecar ("sidecars inherit the GUI's unprivileged identity"). So there is one architecture,
not several: the Tauri Rust backend is an IPC client of `thisconnectd`, and the web frontend
is a view over what that client observes. This document is about how that client, the
Tauri command surface, and the frontend divide responsibility — not about picking between
alternatives SPEC already closed.

## 2. Repo layout

```
/ui
  src-tauri/

                          reimplementation of Request/Response/Event on the Rust side
    src/

      ipc_client.rs        connect/reconnect actor, request correlation, event fan-out
      commands.rs          #[tauri::command] fns, one thin wrapper per Request variant
      tray.rs               tray menu, icon-state updates from ConnectionState
      error.rs              maps IpcError/transport failures to a serializable UI error type
  src/                      Svelte + TS frontend (Vite)
    lib/
      ipc.ts                thin invoke() wrappers + typed event listeners
      types.ts              TS mirror of shared/src/ipc.rs wire shapes (hand-kept, see §7)
      stores/
        connection.ts        ConnectionStatus, derived "daemon reachability" state
        profiles.ts           ProfileSummary[] cache, refetched on mutation
        prompts.ts             current CredentialPrompt | null, queue of at most one
```

This matches `docs/SPEC.md` §3.2's `/ui` line exactly; nothing here restructures the repo
outside that directory.

## 3. IPC client actor (`src-tauri/src/ipc_client.rs`)

One long-lived tokio task, started at app launch, owned in Tauri managed state behind a
`Mutex`/channel handle (never behind a lock held across an `.await` — commands talk to the
actor by message-passing over an `mpsc`, not by locking a shared connection).

**Responsibilities:**
- Own the AF_UNIX connection to the daemon socket (path from the platform default —
  `/run/thisconnect/thisconnectd.sock` on Linux, `/var/run/thisconnect.sock` on macOS —
  overridable by the same env var the daemon honors, for dev).
- Send `ClientMessage::Hello` first on every (re)connection, per SPEC §7.4; refuse to send
  anything else until the daemon's `Hello` answers with a `protocol_version` that
  `check_protocol_version` (already in `shared::ipc`) accepts.
- Maintain a `HashMap<RequestId, oneshot::Sender<Result<Response, IpcError>>>` for in-flight
  requests. `commands.rs` calls generate a fresh `RequestId` (UUID), register the oneshot,
  send, await.
- Fan out every `DaemonMessage::Event` and `DaemonMessage::Prompt` as a Tauri event
  (`app_handle.emit("daemon-event", ...)`, `emit("daemon-prompt", ...)`) — never queued
  behind command results, never polled.
- Reconnect loop: on socket EOF/error, clear all in-flight requests with a synthetic
  `IpcError` (`ErrorCode` needs a `DaemonUnavailable`-shaped case — see §5), emit a
  `connection-lost` Tauri event immediately, then retry with capped exponential backoff
  (250ms → 5s). A reconnect re-sends `Hello`; it does **not** re-issue prior requests —
  the frontend re-fetches (`Status`, `ProfileList`) after seeing `connection-restored`.
- Distinguish **socket-connect failure modes** at the OS level before ever reaching the
  protocol: `ENOENT`/`ECONNREFUSED` → "daemon not running"; `EACCES` → "daemon unreachable:
  group membership" (SPEC §7.1's log-out-and-back-in trap) — this check happens here, once,
  not scattered in the frontend.

**Why an actor, not a lock around a `TcpStream`-like handle:** commands and the event
fan-out both need the connection concurrently (a command's request and an async `>LOG:`
event can interleave, same as the daemon's own management-client contract in SPEC §4.3).
An actor with one reader task and an mpsc command queue keeps "exactly one write in flight,
async events dispatched immediately" — mirroring the daemon's own management-protocol
discipline in SPEC §4.3 point 2, for the same reason.

## 4. Tauri commands (`src-tauri/src/commands.rs`)

One command per `Request` variant, plus `prompt_reply`. Each is a thin
`async fn foo(...) -> Result<T, UiError>` that builds the `Request`, sends it to the actor,
awaits, and maps `Response`/`IpcError` into a frontend-friendly shape (§5). No business
logic lives here — validation, state transitions, and policy all live in the daemon per
SPEC §3.1.4/§6.

```
profile_import(name, config) -> ProfileSummary
profile_list() -> Vec<ProfileSummary>
profile_get(profile_id) -> ProfileSummary
profile_delete(profile_id) -> ()
connect(profile_id) -> ()          // completion means "request accepted"; state changes
                                    // arrive as Event::State, not as this call's return
disconnect() -> ()
status() -> ConnectionStatus
proxy_info() -> ProxyInfo
proxy_stats() -> ProxySessionStats
prompt_reply(prompt_id, reply) -> ()
```

`connect`/`disconnect` deliberately return as soon as the daemon acks the request, not when
the tunnel reaches `Connected`/`Disconnected` — that transition is observed the same way for
a user-initiated connect as for a server-initiated reconnect, through `Event::State`. Two
code paths for the same state transition is exactly the kind of divergence SPEC's watchdog
work spent this cycle eliminating on the daemon side; the UI does not reintroduce it.

## 5. Error surface

A single `UiError` enum crosses the Tauri command boundary (Tauri serializes command
`Err` values to the frontend as-is):

```rust
enum UiError {
    Daemon(IpcError),        // shared::ipc::IpcError, forwarded verbatim
    DaemonUnreachable { reason: DaemonUnreachableReason },
    Timeout,
}
enum DaemonUnreachableReason {
    NotRunning,               // ENOENT / ECONNREFUSED
    PermissionDenied,         // EACCES — surfaced as SPEC §7.1's log-out-and-back-in case
    ProtocolMismatch { daemon_version: String },
}
```

The frontend never renders a generic "something went wrong" for these three cases — each
gets its own copy, per the explicit SPEC §7.1 instruction that `EACCES` must be detected
specifically.

## 6. Event → store mapping

| Backend event | Store updated | Notes |
|---|---|---|
| `Event::State` | `connection.ts` | drives the state machine driving which screen is default |
| `Event::ByteCount` | `connection.ts` | counters only; no history retained beyond current session |
| `Event::Log` | `log.ts` | bounded ring buffer (last 500 lines) — this is the daemon's already-redacted log stream (SPEC §4.4), never raw `>LOG:` |
| `Event::TunnelUp` / `Event::TunnelDown` | `connection.ts` | populates/clears `TunnelInfo` |
| `Event::ProxyListenerUp` / `Event::ProxyListenerDown` | `proxy.ts` | listener address availability; triggers a `proxy_info` refetch rather than carrying the full `ProxyInfo` itself |
| `Event::PromptCancelled` | `prompts.ts` | clears the live prompt if its `prompt_id` matches; a `prompt_reply` sent after this is expected to come back `prompt_expired` and is surfaced as "this prompt timed out", not a generic error |
| `daemon-prompt` (`DaemonMessage::Prompt`) | `prompts.ts` | at most one prompt live; a second `Prompt` while one is unanswered is a daemon-contract violation and is logged, not queued |
| `connection-lost` / `connection-restored` | `connection.ts` (reachability field, separate from `ConnectionState`) | reachability is orthogonal to tunnel state — the tunnel can only be `Disconnected` while unreachable, but "unreachable" itself is not a `ConnectionState` variant |

`ProxySessionStats` has no push event — the Connect/Status and Proxy Info screens fetch
`proxy_stats` on a fixed interval (2s) only while the tunnel is `Connected`, stopping
otherwise. This is a poll, not an architecture change to the IPC protocol; if a future SPEC
revision adds a push event for session stats, this is the one spot that changes.

## 7. TS type mirroring

`shared::ipc` types are hand-mirrored into `ui/src/lib/types.ts`, not code-generated. Given
the wire format is `#[serde(tag = "type", rename_all = "snake_case")]` throughout, the TS
shapes are a direct, mechanical transcription (discriminated unions keyed on `type`). A
generator (`ts-rs`, `specta`) is deliberately not introduced for this first pass — the
protocol surface is ~15 types and codegen tooling is its own maintenance surface; revisit
only if the two drift in practice. Drift risk is bounded by the Rust-side integration test
in §9 that round-trips real daemon messages through `commands.rs` and asserts the JSON shape
matches what `types.ts` expects (a fixture-based test, not a runtime schema check).

## 8. Prompt flow

`CredentialPrompt` (username/password, static challenge, dynamic challenge) renders as a
modal (`PromptDialog.svelte`) that blocks interaction with the rest of the app while a
prompt is outstanding — matching the daemon's own model where the auth attempt is stalled
on exactly one answer. Cancel sends `PromptReply::Cancel` (SPEC: "the daemon aborts the auth
attempt rather than retrying with stale credentials"). TOTP-style challenges
(`echo: false`) render as a masked input; the value is never logged client-side and is
dropped from component state immediately after `prompt_reply` resolves.

## 9. Screens (v1.0 surface)

- **Profiles** — import (paste/file-pick `.ovpn` text → `profile_import`), list, delete.
  Import failures surface the daemon's `ValidationError`/`ValidationReason` (already typed in
  `shared::ipc`) with the offending line, per SPEC §6.
- **Connect/Status** (default view) — current `ConnectionState`, `TunnelInfo` when present,
  byte counters, `local_dns_lookups` rendered verbatim as the leak-proof counter SPEC §5.4 D7
  calls for ("0 local DNS lookups this session"), log tail, connect/disconnect action gated
  on a profile being selected.
- **Proxy Info** — listen address(es), `socks5h://` copy button (never `socks5://`, per
  SPEC §5.4 D8 — enforced by only ever reading `ProxyInfo.socks5h_url`), non-loopback banner
  (SPEC §5.6 L4) rendered as a persistent, non-dismissable banner exactly when
  `!is_loopback_only`, showing bind address and `distinct_remote_peers`.
- **Settings** — `tunnel_fallback_dns` (v1.0 field only), TOTP opt-in toggle with the SPEC §8
  tradeoff copy shown inline, not hidden in a tooltip.
- **Log** — full scrollback of `Event::Log`, filterable by `LogLevel`.
- **Tray** — icon reflects `ConnectionState` (four visual states: disconnected, connecting/
  reconnecting/authenticating, connected, failed), menu: show window, connect/disconnect
  (disabled appropriately), quit. Never the only path to any action the main window exposes.

## 10. Testing

- Rust: unit tests for `ipc_client.rs` framing/correlation/reconnect against a fixture
  socket (mirroring the daemon's own management-codec test style), and the fixture-based
  wire-shape test from §7.
- Manual: `cd ui && npm install && npm run tauri dev` against a real daemon started with
  `cargo run -p thisconnect-daemon --features dev-insecure-ipc` on this Linux box, before any
  screen is called done — covers profile import, connect/disconnect against a real or
  netns-backed session, prompt flow, daemon-restart-mid-session reconnect, and the
  EACCES/not-running unreachable states (simulated by pointing the socket-path env var at a
  wrong path / an unreadable one).
- No attempt this session to test the macOS peer-auth path or a signed build — out of scope
  per the Linux-box environment this work is happening in.

## 11. Explicitly deferred (not gaps — decisions)

- Full-tunnel toggle, MTU field, `allowed_cidrs` UI (SPEC §13 items 4-6) — no UI surface
  until SPEC resolves them.
- UDP ASSOCIATE, plain-HTTP absolute-URI proxying — v1.1 per SPEC §2, no UI surface yet.
- TS type codegen (§7) — revisit only on demonstrated drift.
- Push-based proxy stats — polled for now (§6).
